## Implementation choices

On November 3, 2026, the owner approved **Evolved Getter**, the larger popup and a visible **Settings** button after reviewing the first package. The desktop toolbar popup requests 720 × 600 CSS pixels, with larger type, a shorter header, four color columns, three image columns, side-by-side font details and two-column preferences. Chrome applies its own popup and available-screen bounds; results scroll within the popup. Do not cap the intrinsic root width or window height with viewport units: Chrome auto-sizes the popup from its content, so those caps can lock it to the initial small viewport. The owner reported this in review package 2; the automatic-popup regression reproduced 278 × 346 pixels before removing the caps. A normal tab resized to 720 × 600 had missed the defect. The fixed desktop popup does not promise a 360-pixel mobile layout. Settings has a gear plus a visible label, and selecting it again returns to the previous tool.

Evolved Getter retains the existing product symbol's path geometry and uses a blue-to-deep-violet gradient (`#009CFF`, `#5969FA`, `#6D28D9`). It is used in the toolbar, extension manager and popup header. This is the owner's approved Getter identity change; the separate Aptelum attribution master remains byte-for-byte unchanged. Product PNGs at 16, 32, 48, 128 and 800 pixels are rendered from the SVG using resvg-js 2.6.2 with `fitTo: { mode: "width", value: size }`, transparent background and no font dependency. The renderer is an asset-preparation tool, not a runtime or build dependency.

React 18.2 and JSZip 3.10.1 are retained at exact versions. The former Webpack/Babel/plugin stack was considered for repair. The original two-entry static extension required many packages and separate transforms; one esbuild script handles the shared React UI, background worker and Inspect content bundle with fewer moving parts. There is no framework, backend or service migration. Node 24.18.1 and the dependency lock provide a reproducible install. Development and production both prohibit remote script execution; no web server or secrets are shipped.

The shared popup/side panel UI separates DOM extraction, document orchestration, preferences, downloads and presentation. Scans are ephemeral in the open workspace. A short-lived browser-session transfer preserves verified results during a view switch; retained panels receive an explicit transfer notification; only preferences persist to local storage. Closing the popup discards results and pending preparation except for an unused transfer. Chrome can retain hidden side-panel memory until navigation, rescan or view release; hiding the panel pauses selection. On installation/update, cleanup removes only known Getter result/cache keys and conservatively identified historical URL snapshot keys. Preferences, false options and unknown preference keys survive. The popup retries an idempotent migration on open. Background cleanup never overwrites preferences.

## Access and limits

Settings includes a locally saved System / Light / Dark appearance selector. System is the default for existing and new installations and follows the browser's color preference; explicit Light or Dark overrides it. The eleven display options use labeled native checkbox switches, and the segmented appearance selector uses native radios for keyboard navigation. Failed saves restore the previous selection and appearance. A decorative, packaged SVG globe identifies the hostname; it does not fetch a website logo or request favicon permissions. All settings fit the full desktop popup; constrained screens retain scrolling.

- `activeTab` and `scripting` cover an explicit toolbar invocation. No standing or optional all-site host grants are requested. Scans do not edit page IDs, borders or other DOM content.
- `webNavigation` is retained only to enumerate frames in the selected tab on request; there is no background navigation listener or browsing log. Up to seven same-origin child frames plus the main document are inspected. Browser-provided document IDs are pinned and rechecked. Cross-origin, opaque, inaccessible and excess frames are explicitly reported as omitted; the product does not claim an exhaustive scan of all frames, pseudo-elements, shadow roots or background images.
- Main extraction stops at 4,000 nodes/100 ms; each child at 1,000 nodes/40 ms. Each result category is capped at 500 after aggregation. A five-second orchestration timeout/cancellation invalidates late results; already injected read-only work is bounded, not remotely killed.
- `storage.local` persists display preferences; `storage.session` holds bounded, short-lived workspace transfers. `downloads` starts an explicit download and observes only owned download IDs while its workspace is loaded. Only prepared local blob URLs are passed to Chrome's downloader, so it cannot follow remote redirects or send site cookies. Started, completed, interrupted and unknown are separate messages. No broad download history query is made.
- Previews are opt-in, either in the Images view or through the saved Load previews by default switch. File-size reads and ZIP generation happen only on explicit requests, never during rendering. File-size reads, individual downloads and ZIP fetches require HTTPS without embedded credentials, omit credentials/referrer, reject redirects, and respect browser CORS/activeTab access. The content security policy also restricts connections and preview images to HTTPS (plus packaged images). Hosts that reject access are unavailable without requesting more privileges. Individual downloads use the same bounded fetch path as ZIP preparation. This is a deliberate limit, reported in the UI, rather than restored all-site access.
- ZIP: up to 40 files, 8 MiB each, 32 MiB total, one streamed fetch at a time, eight seconds per fetch, sixty seconds preparation. Preserve supported image MIME extensions; no renaming everything to JPEG. Count skipped/oversized/unavailable images and report zero-success failure. Cancellation stops new requests. ZIP assembly is bounded by the byte cap; cancellation during assembly discards the result before saving. Preparation ends before a separate Save ZIP decision: included/unavailable/omitted counts are visible first, with Save ZIP and Discard actions. Prepared blobs stay only in workspace memory and are discarded on rescan/navigation or when Chrome releases the view; a hidden side panel may be retained. The preparation timer ends before waiting for the person. Create the object URL only when Save is selected. Native Save As may close the popup; the browser Downloads view supplies the final outcome then. Releasing the view releases owned object URLs. A download accepted by Chrome may continue after closing; verify the actual outcome in browser Downloads. Owned URL status observation is capped at two minutes, after which completion is reported as unknown.

## Text, Inspect and workspace expansion (3.0.0)

The owner approved the expanded mocks before implementation, accepted the compact-header Chrome build at `2ba1a0a955f25e421ec80ee660ac3146919ccc8f`, and authorized merge after review and passing checks. The owner requested v3.0 for the expanded feature set. Final independent review identified four edge cases: reselecting a Text source cleared results, open workspaces could overwrite newer preferences, Inspect allowed underlying press handlers, and Text could include visually hidden embedded content. The release corrects these with browser regressions while preserving the accepted layout and intended normal interactions. The human acceptance remains scoped to the compact-header build; the final review assesses these corrections and the owner’s current instruction authorizes merge after passing checks. Colors, Fonts, Images and Text work in either view. Inspect always uses the side panel. Settings saves the toolbar default; the adjacent one-off switch preserves the current tool, queries and verified page data without changing that default. Leaving Inspect for a popup restores the last non-Inspect tool. The side panel follows tab activation in its own window. Navigation clears results rather than reusing an old page snapshot.

The shipping manifest adds only `sidePanel`; it still has no host grants. Chrome 141 is the minimum because switching back uses `sidePanel.close({windowId})`. Calls to `sidePanel.open` originate in the click's message handler. The transfer is consumed once through session storage with a 30-second validity check, document ID validation and worker cleanup. Unconsumed data may remain in browser-session memory if Chrome suspends the cleanup timer; it cannot be restored after expiration and disappears with session storage. The selected DOM element is held weakly by the picker, not saved to local storage.

Text provides Page, Main content and Selection. Main uses the first main/role=main/article region with a page fallback. It follows source reading order, which may differ from CSS visual order. It omits hidden content and form values, preserves inline text without ancestor duplicates, and reads accessible same-origin child documents in place. Cross-origin/opaque frames are reported as omitted. Text in shadow components, generated pseudo-content, canvas and browser-native controls is not included. Text work stops at 12,000 nodes, 150,000 characters, 1,000 blocks or 180 ms. Limits are disclosed. Selection uses the main document's current selection. Find filters blocks; Copy text and Save .txt use the full extracted source, while block copy uses one block.

Inspect runs only when its panel tool is open. Selection remains active across picks; Escape, Pause or the Select on page switch restores normal interaction while retaining the selected result. No page element's IDs, styles or event attributes are rewritten. A temporary isolated overlay highlights hover targets. Disconnect, navigation and component cleanup remove the overlay, handlers and mutation observer. Visibility changes immediately pause selection and remove the picker overlay/handlers when Chrome retains a hidden panel. Main-document and open-shadow elements are supported; embedded-page interiors report unavailable. Removing a selected node clears its result. Copy revalidates the current document and selected element.

The approved compact Inspect header shows only the selected element name above the section tabs. The type badge, text preview and breadcrumb trail have been removed to leave more room for values. Long names stay on one line with their full selector available on hover and in Element details.

Styles, Layout, Effects and Element are separate, searchable sections. Show all stays within the section. Layout includes rendered bounds, an untransformed box model, flex/grid, size, spacing, position and overflow. Effects starts with non-default gradients, shadows, borders, filters and transforms. Element details include available attributes, text, links, and image source/alt/rendered/natural dimensions; absent values are labeled Not set. Copy CSS previews computed CSS and excludes DOM attributes. CSS snapshots stop at 600 properties, 180,000 characters or 150 ms; individual values are capped at 4,096 characters, attributes at 80, text at 4,000 characters/500 nodes and selector at 2,048 characters. Partial snapshots are labeled.

## Usage percentages and ordering

The owner approved preserving the existing color and font cards, adding percentage labels (for example, “31.4% of color uses” and “72.7% of font uses”), and a Most used first / Least used first button. Colors and Fonts each start most-used first and retain separate order choices while switching tools or transferring between popup and side panel. New scans reset the order. Sorting changes card order without changing values copied to the clipboard or which summary font styles are shown.

Color percentages divide a color’s occurrences by all detected nontransparent text/background color occurrences in scanned visible elements. Each inspected element can contribute one of each, even when its text color is inherited; this is not painted screen area. Font percentages use the existing captured element types and computed font styles (including element type, family, size, weight, spacing and line height), not character counts or actual font glyph detection. Summary mode shows the most-used style per element type, and its denominator includes hidden styles. Both totals combine permitted frames and include detected uses omitted by item caps. Existing time/node/frame limits still apply and partial scans are disclosed. Frequencies for a style excluded by a per-frame item cap cannot be ranked exhaustively across the whole page.

Percentages use one decimal place; nonzero values that would round to zero show “<0.1%.” Equal counts use a deterministic value/style tie break. The info icon explains the denominator, rounding and partial-scan scope. This feature adds no permissions, storage history or network requests. It remains a 3.0.0 Chrome test candidate pending human QA and a separate release decision.

## Verification and remaining owner QA

`npm run check` covers extraction without host mutation, caps, preference migration, tab/navigation/document rejection, permissions, exact logo bytes and package inventory. Download tests cover failed/CORS/oversized/cancelled paths and start/completion races. Browser tests load the built extension into a fresh Chromium profile with **test-only localhost host grants** and synthetic pages, exercise real script injection, stored options, frame omission, navigation and actual image/ZIP downloads. HTTPS image responses are fulfilled by synthetic browser routes; this verifies URL/CSP/redirect behavior, not an actual TLS server. Insecure URLs and downgrade redirects must not reach the local HTTP endpoint from the extension. The sizing regression opens the actual action popup with `chrome.action.openPopup()` and measures only `chrome.extension.getViews({ type: "popup" })` from an inactive extension tab. Viewport emulation is disabled, a 1600 × 1200 headless screen supplies desktop space, and the test checks automatic 720 × 600 bounds, more than 350 pixels of results height, a visible footer, no horizontal overflow and all eleven preferences fitting. This is an automated headless popup check, not a physical toolbar click or a human-QA verdict. A second actual-popup case on an 800 × 600 screen checks scrolling to the last preference, image download, ZIP and footer actions when Chrome limits the viewport height. The footer may scroll on a constrained screen; fixed footer visibility is asserted only at the tested full desktop popup size. The standalone-tab light/dark checks remain separate. The workspace regression also opens native popup and side-panel targets and uses CDP user activation in the target itself to exercise view switches, retained-panel restoration, Text query preservation and Inspect routing/cleanup. This is simulated browser activation, not a physical user click. Text and Inspect fixture tests cover source selection, hidden/form omissions, exact clipboard submissions, actual text download bytes, continuous selection, pause/resume, all sections, long values, open shadows, deleted nodes, restricted pages and tab invalidation. This is not a claim that the shipping activeTab toolbar permission gesture has been qualified. The shipped manifest is separately checked to contain no host grants.

Automated browser testing is a required quality gate for Getter changes affecting the popup or browser-visible behavior. `npm run test:browser` runs in the existing `Getter checks` CI job; required failures block readiness for human QA. Record exact source, run, environment, outcomes and limits, including test-only grants. Agent-operated native checks supplement fixture gaps such as toolbar access and Save As; they are still automated/agent verification, not a human-QA verdict. Verify repository protection settings before describing any gate as server-enforced.

Before merge, independently review the immutable candidate and complete applicable CI/browser gates. Passing those gates makes the candidate ready for human QA. **Human QA has the final merge decision.** Record the human's verdict and explicit merge authorization for the candidate; design approval, agent-operated browser checks and a request for QA do not supply that verdict. Human acceptance does not waive failed required gates, and automation or an agent must not merge solely because checks are green. If source changes, retain the prior verdict's scope and obtain the current review and renewed QA needed for that change. A genuinely non-UI change can record browser/human UI QA as not applicable with a scope-based reason; required CI, independent review and applicable human merge authority remain. This local clarification follows the owner's instruction and is not an adoption of shared company policy.

- Fresh install and update from 2.0.0 with custom options; no lost preferences, no legacy snapshots, toolbar stays enabled.
- Popup and side panel defaults, one-off switching, Text page/main/selection copy and Save .txt, continuous Inspect selection/pause/resume, expanded sections, CSS preview, long values, and tab/navigation invalidation.
- Palette layout, keyboard focus/tab sequence, System / Light / Dark appearance (including persistence after reopening), display switches, hostname globe, colors and alpha copy, detailed/summary fonts and settings.
- Blocked pages, empty pages, slow/large pages, denied/opaque/cross-origin frames, worker suspension and recovery, cancellation and actionable errors.
- Images, unavailable previews, file-size failures, secure individual downloads and bounded/partial ZIP exports; close during preparation and during an in-progress ZIP. Browser download completion must match the UI. Current popup-lifetime limitations are explicit above and must be assessed in QA.
